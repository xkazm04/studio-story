Create `src/app/features/story/sub_SceneEditor/extensions/inlineDiffExtension.ts`:
- TipTap Extension.create({ name: 'inlineDiff' })
- addStorage(): `{ diffs: DiffRange[], originalText: string, originalFrom: number, originalTo: number, newText: string, active: false }`
- Export `DiffRange` interface: `{ from: number, to: number, type: 'addition' | 'deletion', text: string }`
- addProseMirrorPlugins(): single Plugin with PluginKey('inlineDiff'). The decorations prop reads storage.diffs and creates Decoration.inline for each:
  - 'addition': class `bg-emerald-500/20 text-emerald-300 decoration-emerald-400`
  - 'deletion': class `bg-red-500/20 line-through text-red-400 opacity-60`
- addCommands():
  - `showDiff({ originalText, newText, from, to })`: uses diff-match-patch to compute diffs between originalText and newText, maps diff positions to document positions starting at `from`, stores in storage, sets active=true
  - `acceptDiff()`: performs a single transaction replacing content from originalFrom to originalTo with newText, clears storage, sets active=false
  - `rejectDiff()`: clears storage diffs, sets active=false (document unchanged since decorations are visual only)
  - `isDiffActive()`: returns storage.active

CRITICAL: Per research anti-pattern guidance -- the document is NOT modified during diff preview. Only decorations are applied. The actual text replacement happens ONLY on acceptDiff(). For the diff preview, temporarily insert the new text and mark additions/deletions with decorations. On reject, undo the temporary insertion. Use a single transaction for the temporary preview insertion that can be cleanly undone.

REVISED APPROACH: Actually, to keep the document truly unchanged during preview while showing both additions and deletions, use this strategy:
1. On showDiff: replace the selected range with the NEW text in a transaction, but track the diff ranges. Mark additions with green decorations, mark text that was in original but not in new (deletions) by inserting them back as decoration-only nodes or by using a widget decoration showing strikethrough text.
2. Simpler alternative per research: Replace text with new text, add decorations. On Accept: just clear decorations (text is already replaced). On Reject: undo the transaction (editor.commands.undo()).

Use the simpler approach: on showDiff, replace text in a single transaction, add decorations. On accept, clear decorations. On reject, undo the replacement transaction. Store the undo step count to ensure correct undo depth.

Create `src/app/features/story/sub_SceneEditor/extensions/aiWritingExtension.ts`:
- TipTap Extension.create({ name: 'aiWriting' })
- addStorage(): `{ isProcessing: false, currentTool: null as WritingToolType | null, error: null as string | null }`
- addCommands():
  - `runWritingTool({ tool, projectId, sceneId, options })`: sets isProcessing=true, gets selection from editor state, calls POST /api/ai/writing with selected text + tool + context, on success calls inlineDiff.showDiff with result, sets isProcessing=false. On error, sets error message and isProcessing=false.
  - `clearWritingState()`: resets storage to defaults
