  <action>
    1. Create `packages/dzin/core/src/state/hooks.ts`:
       - `useWorkspaceState(engine: StateEngine<WorkspaceState>)`:
         - Uses `useSyncExternalStore` for tear-free reads (subscribe + getState + getState for SSR)
         - Returns `{ state, undo, redo, canUndo, canRedo, history }`
         - `undo` and `redo` are stable callbacks via `useCallback`
       - `useUndoRedoKeyboard(undo, redo, canUndo, canRedo)`:
         - Adds `keydown` listener on `document`
         - Ctrl+Z (no shift) -> undo, Ctrl+Shift+Z -> redo, Ctrl+Y -> redo
         - Uses `e.preventDefault()` to block browser default undo
         - Handles both `ctrlKey` and `metaKey` (Mac Cmd)
         - Cleans up on unmount

    2. Create `packages/dzin/core/src/state/conflict.ts`:
       - Maintains a Set<string> of locked JSON Pointer paths
       - `acquireUserLock(path: string)`: adds to locked set
       - `releaseUserLock(path: string)`: removes from locked set
       - `getUserLockedPaths()`: returns copy of locked paths
       - `applyLLMPatchWithConflictCheck(stream: StreamController, patch: Operation)`: checks if patch.path starts with any locked path. If locked, return false (drop). If unlocked, call stream.applyPatch(patch), return true.

       Per user decision: "User wins on conflict -- if user is directly manipulating state while LLM is streaming changes, user's changes take priority. Conflicting LLM changes are silently dropped or queued."

    3. Create integration test that exercises the full engine -> streaming -> undo flow:
       - Create engine with initial workspace state
       - Dispatch LLM patches (add 3 panels) as single group
       - Verify state has 3 panels
       - Undo -> state has 0 panels
       - Redo -> state has 3 panels again
       - Start stream, apply 2 patches progressively, commit -> new undo group
       - Undo -> reverts the stream batch
       - Test conflict: lock a panel path, stream a patch to that path (dropped), verify state unchanged for that path

    4. Write tests RED first, then implement GREEN, then REFACTOR.
