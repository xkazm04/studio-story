  <files>src/lib/claude-terminal/persistent-session.ts, src/lib/claude-terminal/__tests__/persistent-session.test.ts, src/app/api/claude-terminal/intent/route.ts</files>
  <behavior>
    - createPersistentSession returns object with sessionId, status, send, restart, destroy
    - First send() call starts a CLI execution and captures sessionId from init event
    - Subsequent send() calls reuse sessionId via --resume flag
    - getOrCreateSession returns existing session if status !== 'disconnected'
    - getOrCreateSession uses globalThis to survive HMR
    - send() returns CLIResponse with the result text and any tool results
    - restart() destroys current session and creates fresh one
    - After 3 consecutive errors, status becomes 'disconnected'
    - POST /api/claude-terminal/intent accepts { context: string }, calls session.send(), returns LLMResponse JSON
  </behavior>
  <action>
Create `src/lib/claude-terminal/persistent-session.ts`:
- `PersistentSession` interface: `{ sessionId: string | null; status: 'idle' | 'busy' | 'error' | 'disconnected'; send(prompt: string): Promise<CLIResponse>; restart(): Promise<void>; destroy(): void }`
- `CLIResponse` type: `{ text: string; toolResults?: Array<{ name: string; result: unknown }> }`
- `createPersistentSession(projectPath: string)`: wraps existing `startExecution()` from cli-service.ts. Tracks sessionId from first init event. On subsequent calls, passes `--resume ${sessionId}`. Tracks consecutive errors; after 3, sets status to 'disconnected'.
- `getOrCreateSession(projectPath: string)`: uses `globalThis as unknown as { __dzinPersistentSession: PersistentSession | undefined }` pattern. Returns existing if not disconnected, otherwise creates new.

Create `src/app/api/claude-terminal/intent/route.ts`:
- `POST` handler: reads `{ context }` from request body, calls `getOrCreateSession(process.cwd()).send(context)`, parses CLI response into `LLMResponse` shape, returns JSON.
- On session error: returns `{ status: 'error', error: message }` with 200 status (transport handles error routing).

Write tests for persistent-session.ts mocking startExecution/cli-service.
